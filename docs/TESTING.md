# Автотесты Котобы

Документ описывает стратегию, текущее покрытие и правила добавления тестов.

## Зачем

Главные риски проекта — не в вёрстке, а в тихих ошибках:

- SRS неправильно пересчитывает интервалы;
- миграция данных портит старые карточки;
- импорт резервной копии затирает прогресс;
- фильтры подборок и сессий выдают не те карточки.

Именно эти места покрываются в первую очередь.

## Стек

- **Vitest 5** — работает на той же конфигурации Vite, без отдельного сборщика.
- **Окружение `node`** — для чистой логики. Компонентные тесты используют `jsdom` и Testing Library.
- **V8 coverage** — встроенный отчёт без дополнительной инфраструктуры.
- Фикстуры — `src/test/factories.ts`.

## Команды

```bash
npm test            # один прогон
npm run test:watch  # режим наблюдения
npm run test:coverage
npm run check       # типы + тесты
```

Тесты не входят в `npm run build`: сборка остаётся быстрой, а полная проверка — это `npm run check`.

## Где лежат тесты

Рядом с модулями: `src/lib/srs.test.ts`, `src/lib/normalize.test.ts` и так далее.
Тесты не импортируются приложением и не попадают в бандл.

## Что уже покрыто

- **SRS:** все оценки, границы ease, максимальный интервал, ручное «выучено», форматирование интервалов.
- **Данные:** нормализация и миграции, настройки, история, корзина, свои наборы, письменность карточек.
- **Резервные копии:** валидация файла, замена и объединение.
- **Импорт CSV/TSV:** определение разделителя, кавычки, переводы строк, BOM, кодировки.
- **Корзина:** удаление, восстановление, срок хранения, «никогда».
- **Колоды:** объединение, разделение, перенос между установками, права встроенных колод.
- **Сессии:** очередь с дневными лимитами, порядок, практика.
- **Свои наборы:** все фильтры, включая письменность.
- **Статистика:** календарь активности, серия, точность, прогнозы, рекорды, нагрузка.
- **Транскрипции:** ромадзи и кириллица.
- **Локали:** наличие строк во всех языках и формы множественного числа.
- **Выпадающий список:** выбор мышью и клавиатурой, отключённые пункты, закрытие по Escape.
- **Боковое меню:** aria-состояние, сохранение свёрнутости, подписи остаются в разметке.
- **Просмотр карточки и озвучка:** общая модалка просмотра и кнопка произнесения примера.

## Принципы

1. Тестируем поведение, а не внутренние детали.
2. Каждый тест фиксирует один сценарий и называется по-человечески.
3. Время и случайность подставляются явно (`now`, `shuffle` не влияет на состав).
4. Никакой сети и файловой системы в юнит-тестах.
5. Тест не должен зависеть от текущего языка системы.
6. Если тест ловит спорное поведение — сначала решаем, баг это или норма, и только потом закрепляем.

## Целевое покрытие

- Критичные модули (`srs`, `normalize`, `backup`, `trash`, `deck-ops`, `study`, `stats`): **80%+**.
- Остальная логика: по мере изменения.
- 100% не гоняем: презентационные функции и платформенные обёртки тестировать дороже, чем полезно.

## Что пока не покрыто

- `storage.ts` — IndexedDB и localStorage, нужен `fake-indexeddb` и DOM-окружение.
- `tts.ts`, `updates.ts` — зависят от браузера и сети.
- `electron/*.cjs` — главный процесс, нужны интеграционные тесты Electron.
- Остальные React-компоненты и хуки — следующий этап.

## Следующие этапы

1. **Компоненты и хуки:** `useCardBrowserFilters`, `useDeckCardFilters`, формы карточек, панель корзины.
2. **Хранилище:** `fake-indexeddb` для веб-ветки и проверка частей данных.
3. **Electron:** smoke-тест запуска и IPC-контрактов.
4. **CI:** прогон `npm run check` на каждый push, когда появится доступ к workflow.

## Как добавить тест

1. Найдите модуль и его публичное поведение.
2. Соберите данные через фабрики, а не копированием объектов.
3. Проверьте границы: пустые данные, отсутствующие поля, лимиты, старое состояние.
4. Запустите `npm test` — новый тест должен падать до реализации и проходить после.
